# Port Map — Bot Army Starter on Vagrant

**Purpose:** Track which ports vagrant forwards, what services use them inside containers, and what clients need to connect to.

## Vagrant Port Forwards (Host ← VM)

| Host Port | VM Port | Service | Purpose |
|-----------|---------|---------|---------|
| **54222** | 4222 | NATS Client | Bots publish/subscribe; agents connect here |
| **58222** | 8222 | NATS Monitor | HTTP health checks, metrics |
| **55432** | 5432 | PostgreSQL | Database (bots write state) |
| **51434** | 11434 | Ollama | LLM model API |
| **39900** | 39900 | MCP Server | MCP protocol endpoint (if enabled) |

## Inside Containers (Docker Compose)

These ports are exposed by bot containers. Accessible via hostname inside compose network:

| Port | Service | Bot/Container | Purpose |
|------|---------|---------------|---------|
| **4222** | NATS | nats | Client connections |
| **8222** | NATS Monitor | nats | HTTP healthz, stats |
| **5432** | PostgreSQL | postgres | Database connections |
| **11434** | Ollama | ollama | Model serving |
| **39900** | MCP | mcp_bot (if running) | MCP requests |
| **3000–3999** | Web/Discord | Various | Discord webhooks, web dashboards (future) |

## Usage Examples

**From host machine (macOS):**
```bash
# Check NATS is responding
curl http://localhost:58222/healthz

# Query PostgreSQL
psql -h localhost -p 55432 -U postgres -d bot_army

# Query Ollama models
curl http://localhost:51434/api/tags

# NATS request/reply
nats request --server nats://localhost:54222 bridge.task.list '{}'
```

**From inside vagrant VM:**
```bash
# Inside VM, bots connect to nats:4222 (docker internal network)
# No localhost needed — service discovery works

# From SSH to VM, can access Docker services:
curl http://localhost:8222/healthz
curl http://localhost:11434/api/tags
```

**From Docker compose containers:**
```bash
# Containers use service names (defined in docker-compose.yml)
# Example in a bot's config:
NATS_SERVERS=nats://nats:4222
DATABASE_URL=postgres://postgres:postgres@postgres:5432/bot_army
OLLAMA_URL=http://ollama:11434
```

## Port Allocation Strategy

**Why these specific ports?**
- **54222+**: High ports (> 49152) avoid conflicts with well-known services
- **Offset from container ports**: 54222 (host) = 4222 (container), easy to remember
- **Sequential groups**: 54000s for infra, 51000s for LLM, 39000s for APIs

**Adding new services:**
1. Assign a high port on host (54000–55999)
2. Assign internal port inside container (4000–5999 range)
3. Add to Vagrantfile:
   ```ruby
   [54223, 4223],  # New NATS backup cluster (example)
   ```
4. Update this PORTMAP.md
5. Export from docker-compose.yml or configure port explicitly

## Docker Compose Port Exposure

The docker-compose.yml (generated by wizard) exposes ports like:

```yaml
services:
  nats:
    ports:
      - "54222:4222"    # NATS client (host:container)
      - "58222:8222"    # NATS monitor
  postgres:
    ports:
      - "55432:5432"
  ollama:
    ports:
      - "51434:11434"
```

When bots run inside the compose network:
- They connect to `nats:4222` (not localhost)
- Database at `postgres:5432` (not localhost)
- No port mapping needed for inter-service communication

## Firewall & Security

**On macOS Vagrant + Parallels:**
- Forwarded ports (`54222`, etc.) accessible from host only
- Not exposed to network by default
- If you need external access, configure in Vagrantfile

**On other platforms (VirtualBox, etc.):**
- May need explicit firewall rules
- Check your hypervisor's networking config

## Troubleshooting

**Port already in use:**
```bash
# Find what's using port 54222
lsof -i :54222

# Change Vagrantfile + reboot:
[54223, 4222],  # Use different host port
```

**Can't reach PostgreSQL from host:**
- Check `docker compose ps` (postgres container running?)
- Verify port forward in Vagrantfile
- Try: `telnet localhost 55432`

**NATS monitor not responding:**
- Curl: `curl http://localhost:58222/healthz`
- Check container logs: `docker compose logs nats`
